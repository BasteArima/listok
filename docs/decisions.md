# Решения

Формат: номер, дата, решение, почему. Новые решения добавляются в конец, старые не переписываются: если решение пересмотрено, пишется новое со ссылкой на старое.

**D-001 · 2026-10-03 · Веб-сервис вместо Telegram-бота.** Больше контроля: списки, ссылки фидов, история, права. Telegram остаётся необязательным каналом уведомлений.

**D-002 · 2026-10-03 · Хостинг на homesrv.** Там уже Portainer и NPM. Если сервис упадёт, роутеры живут с последним файлом, поэтому особая отказоустойчивость не нужна.

**D-003 · 2026-10-03 · htmx, а не SPA.** Интерфейс в основном из форм, таблиц, diff и статусов. Сборка фронта не нужна, получается один бинарник. Визуально разницы нет. Для мелкой интерактивности Alpine.js.

**D-004 · 2026-10-03 · Роутеры только сами тянут данные, long-poll.** Роутеры за CGNAT (аул) или неизвестно где (товарищ), входящего доступа к ним нет. Long-poll даёт применение почти мгновенно без опроса раз в минуту.

**D-005 · 2026-10-03 · В forkop подключается локальный путь, не URL.** С URL после ребута возникает гонка: rule-set не регистрируется. Локальный путь импортируется синхронно. Плюс агент контролирует, когда вызывать `list_update`. См. `forkop-integration.md`.

**D-006 · 2026-10-03 · Токены фидов хранятся открыто, остальные токены как хеш.** Ссылку фида нужно показывать в интерфейсе повторно. Она даёт только чтение списков. Сессии, API-токены и токены агентов дают действия, поэтому хранится только sha256.

**D-007 · 2026-10-03 · Агент на ucode.** На роутере нет python и jq, а для clash API нужен разбор JSON. ucode уже стоит, на нём написан forkop.

**D-008 · 2026-10-03 · SQLite через modernc.org/sqlite.** Без CGO: проще сборка и distroless-образ. Нагрузка ничтожная.

**D-009 · 2026-10-03 · По умолчанию добавляется eTLD+1.** forkop ставит домены как `domain_suffix`, а сайты почти всегда тянут поддомены. Добавить ровно хост можно флажком.

**D-010 · 2026-10-03 · Права на уровне списка + предложения.** Товарищ может и вести свои списки, и предлагать в общий отдельные строки или целый список (как вложенный). Решает владелец.

**D-011 · 2026-10-03 · Домен `listok.baste.ru`.**

**D-012 · 2026-10-03 · Интерфейс открыт наружу, защита паролем.** Добавлять записи нужно с телефона откуда угодно, поэтому access list NPM не ставим. Компенсируем ограничением частоты входа, argon2id и CSRF-защитой. Первый админ создаётся из env или через `/setup` с одноразовым токеном из лога (`deploy.md`).

**D-013 · 2026-10-03 · Сторожевая запись `listok-sentinel.invalid` в каждом фиде.** forkop регистрирует rule-set в DNS-правилах, только если на момент генерации в нём есть домены, а пустой rule-set не регистрирует вовсе. Сторожевая запись гарантирует, что добавленное позже работает без рестарта (`forkop-integration.md`).

**D-014 · 2026-10-03 · Репозиторий публичный** (`github.com/BasteArima/listok`). В репозиторий не попадают адреса LAN, токены, реальные списки пользователя и данные .env. Примеры только с заглушками.

**D-015 · 2026-10-04 · Вход: argon2id + сессии в БД.**
- **Пароль**: argon2id `m=64МиБ, t=3, p=2` (RFC 9106). Параметры записаны в хеше, так что их можно менять без миграции.
- **Сессия**: случайные 32 байта в cookie `listok_session`, в БД хранится sha256. Срок 30 дней, скользящий: продлевается не чаще раза в 5 минут.
- **Cookie**: `HttpOnly`, `SameSite=Lax`, `Secure` при https. Lax выбран, чтобы ссылки из Telegram и «Поделиться» открывались уже залогиненными.
- **CSRF**: `http.CrossOriginProtection`, без токенов в формах.
- **Ограничение попыток**: в памяти, сбрасывается при рестарте.
  - Логин+IP: 5 неудач за 15 мин, дальше блокировка от 1 мин, удваивается до 1 ч.
  - IP: 20 неудач за 15 мин, общий лимит и на перебор setup-токена.
- **Защита от перебора логинов**: если пользователя нет, всё равно тратится время на проверку хеша, чтобы по задержке нельзя было понять, существует ли логин.

**D-016 · 2026-10-04 · Setup-токен печатается в лог целиком.** Это единственное исключение из правила «токены не логировать». Без этого владелец не узнает токен. Токен живёт только в памяти до создания админа или рестарта, а перебор ограничен.

**D-017 · 2026-10-04 · История пишется с первого изменения.** Любая правка записей идёт через `store.Mutate`: одна операция = одна версия списка с `entry_changes`. Экран истории и откат сделаем позже, а данные для них копятся уже сейчас.

**D-018 · 2026-10-04 · Правила добавления.** Запись, уже покрытая **этим же** списком (точный дубль или домен-родитель/подсеть шире), не добавляется. Покрытие **другим** списком только предупреждает: списки могут подключаться к разным фидам. Покрытие считается только по видимым пользователю спискам, чужие не раскрываются. Выключенные записи покрытия не дают.

**D-019 · 2026-10-04 · Статика с версией по хешу.** `?v=<sha256 статики>` в ссылках + `immutable` на год. Без этого после обновления браузер держал старый CSS (поймали на локальной проверке).

**D-020 · 2026-10-04 · htmx 2.0.11 лежит в репозитории.** Скачан с jsDelivr, sha256 сверен с опубликованным jsDelivr (`1v3HXyBOa976mbab8ebUrGm4o2T3eSn0XBNHa0AA9xc=`). CDN в рантайме не используется. При обновлении сверять хеш так же.

**D-021 · 2026-10-04 · Как устроен откат.** Откат к версии N: текущее состояние → отменить изменения всех версий новее N в обратном порядке (`history.Reconstruct`) → разница с текущим (`history.Diff`) → применить одной новой версией `source=rollback` внутри той же транзакции. Так корректно обрабатываются записи, удалённые и добавленные заново, и цепочки внутри одной версии (проверено против прямого применения на всех версиях). Если состояние уже совпадает, версия не создаётся. Записи, возвращённые откатом, получают автора отката и новое время создания: исходные `added_by`/`created_at` в истории не хранятся.

**D-022 · 2026-10-04 · Кеш фида по версиям списков.** Ключ — «id:версия» всех входящих списков; совпал — отдаём готовое тело и ETag. Любая правка поднимает версию, поэтому не нужна инвалидация из сервиса списков. Long-poll (этап 2) будет опираться на тот же ключ.

**D-023 · 2026-10-04 · Состав фида проверяется при каждой отдаче.** Видимость списков для владельца роутера считается в момент запроса, а не только при сохранении, — отзыв доступа сразу убирает список из фида. Вложенные списки наследуют доступ от родителя.

**D-024 · 2026-10-04 · Токен фида — 43 символа base62.** ~256 бит, только буквы и цифры: не ломается ни в одном поле URL. Валидатор forkop для `domain_ip_lists` принимает любой `http(s)://` (проверено в `config/validator.uc`).

**D-025 · 2026-10-04 · Образ собирается в GitHub Actions, не на сервере.** Как у OpenFront: GHCR `:latest` + `:sha-<7>`, сборка только после зелёных тестов. На homesrv нет Go и исходников, откат — сменой тега. Порт `172.17.0.1:8097` (8096 занят Jellyfin), `network_mode: bridge` из-за исчерпанного пула сетей Docker.
