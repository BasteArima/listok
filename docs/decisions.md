# Решения

Формат: номер, дата, решение, почему. Новые решения добавляются в конец, старые не переписываются: если решение пересмотрено, пишется новое со ссылкой на старое.

**D-001 · 2026-10-03 · Веб-сервис вместо Telegram-бота.** Больше контроля: списки, ссылки фидов, история, права. Telegram остаётся необязательным каналом уведомлений.

**D-002 · 2026-10-03 · Хостинг на домашнем сервере автора.** Там уже Portainer и NPM. Если сервис упадёт, роутеры живут с последним файлом, поэтому особая отказоустойчивость не нужна.

**D-003 · 2026-10-03 · htmx, а не SPA.** Интерфейс в основном из форм, таблиц, diff и статусов. Сборка фронта не нужна, получается один бинарник. Визуально разницы нет. Для мелкой интерактивности Alpine.js.

**D-004 · 2026-10-03 · Роутеры только сами тянут данные, long-poll.** Роутеры бывают за CGNAT или в чужих сетях, входящего доступа к ним нет. Long-poll даёт применение почти мгновенно без опроса раз в минуту.

**D-005 · 2026-10-03 · В forkop подключается локальный путь, не URL.** С URL после ребута возникает гонка: rule-set не регистрируется. Локальный путь импортируется синхронно. Плюс агент контролирует, когда вызывать `list_update`. См. `forkop-integration.md`.

**D-006 · 2026-10-03 · Токены фидов хранятся открыто, остальные токены как хеш.** Ссылку фида нужно показывать в интерфейсе повторно. Она даёт только чтение списков. Сессии, API-токены и токены агентов дают действия, поэтому хранится только sha256.

**D-007 · 2026-10-03 · Агент на ucode.** На роутере нет python и jq, а для clash API нужен разбор JSON. ucode уже стоит, на нём написан forkop.

**D-008 · 2026-10-03 · SQLite через modernc.org/sqlite.** Без CGO: проще сборка и distroless-образ. Нагрузка ничтожная.

**D-009 · 2026-10-03 · По умолчанию добавляется eTLD+1.** forkop ставит домены как `domain_suffix`, а сайты почти всегда тянут поддомены. Добавить ровно хост можно флажком.

**D-010 · 2026-10-03 · Права на уровне списка + предложения.** Товарищ может и вести свои списки, и предлагать в общий отдельные строки или целый список (как вложенный). Решает владелец.

**D-011 · 2026-10-03 · Домен — только в `LISTOK_BASE_URL`.** Реальный домен в репозитории не упоминается, в примерах `listok.example.com`.

**D-012 · 2026-10-03 · Интерфейс открыт наружу, защита паролем.** Добавлять записи нужно с телефона откуда угодно, поэтому access list NPM не ставим. Компенсируем ограничением частоты входа, argon2id и CSRF-защитой. Первый админ создаётся из env или через `/setup` с одноразовым токеном из лога (`deploy.md`).

**D-013 · 2026-10-03 · Сторожевая запись `listok-sentinel.invalid` в каждом фиде.** forkop регистрирует rule-set в DNS-правилах, только если на момент генерации в нём есть домены, а пустой rule-set не регистрирует вовсе. Сторожевая запись гарантирует, что добавленное позже работает без рестарта (`forkop-integration.md`).

**D-014 · 2026-10-03 · Репозиторий публичный** (`github.com/BasteArima/listok`). В репозиторий не попадают адреса LAN, токены, реальные списки пользователя и данные .env. Примеры только с заглушками.

**D-015 · 2026-10-04 · Вход: argon2id + сессии в БД.**
- **Пароль**: argon2id `m=64МиБ, t=3, p=2` (RFC 9106). Параметры записаны в хеше, так что их можно менять без миграции.
- **Сессия**: случайные 32 байта в cookie `listok_session`, в БД хранится sha256. Срок 30 дней, скользящий: продлевается не чаще раза в 5 минут.
- **Cookie**: `HttpOnly`, `SameSite=Lax`, `Secure` при https. Lax выбран, чтобы ссылки из Telegram и «Поделиться» открывались уже залогиненными.
- **CSRF**: `http.CrossOriginProtection`, без токенов в формах.
- **Ограничение попыток**: в памяти, сбрасывается при рестарте.
  - Логин+IP: 5 неудач за 15 мин, дальше блокировка от 1 мин, удваивается до 1 ч.
  - IP: 20 неудач за 15 мин, общий лимит и на перебор setup-токена.
- **Защита от перебора логинов**: если пользователя нет, всё равно тратится время на проверку хеша, чтобы по задержке нельзя было понять, существует ли логин.

**D-016 · 2026-10-04 · Setup-токен печатается в лог целиком.** Это единственное исключение из правила «токены не логировать». Без этого владелец не узнает токен. Токен живёт только в памяти до создания админа или рестарта, а перебор ограничен.

**D-017 · 2026-10-04 · История пишется с первого изменения.** Любая правка записей идёт через `store.Mutate`: одна операция = одна версия списка с `entry_changes`. Экран истории и откат сделаем позже, а данные для них копятся уже сейчас.

**D-018 · 2026-10-04 · Правила добавления.** Запись, уже покрытая **этим же** списком (точный дубль или домен-родитель/подсеть шире), не добавляется. Покрытие **другим** списком только предупреждает: списки могут подключаться к разным фидам. Покрытие считается только по видимым пользователю спискам, чужие не раскрываются. Выключенные записи покрытия не дают.

**D-019 · 2026-10-04 · Статика с версией по хешу.** `?v=<sha256 статики>` в ссылках + `immutable` на год. Без этого после обновления браузер держал старый CSS (поймали на локальной проверке).

**D-020 · 2026-10-04 · htmx 2.0.11 лежит в репозитории.** Скачан с jsDelivr, sha256 сверен с опубликованным jsDelivr (`1v3HXyBOa976mbab8ebUrGm4o2T3eSn0XBNHa0AA9xc=`). CDN в рантайме не используется. При обновлении сверять хеш так же.

**D-021 · 2026-10-04 · Как устроен откат.** Откат к версии N: текущее состояние → отменить изменения всех версий новее N в обратном порядке (`history.Reconstruct`) → разница с текущим (`history.Diff`) → применить одной новой версией `source=rollback` внутри той же транзакции. Так корректно обрабатываются записи, удалённые и добавленные заново, и цепочки внутри одной версии (проверено против прямого применения на всех версиях). Если состояние уже совпадает, версия не создаётся. Записи, возвращённые откатом, получают автора отката и новое время создания: исходные `added_by`/`created_at` в истории не хранятся.

**D-022 · 2026-10-04 · Кеш фида по версиям списков.** Ключ — «id:версия» всех входящих списков; совпал — отдаём готовое тело и ETag. Любая правка поднимает версию, поэтому не нужна инвалидация из сервиса списков. Long-poll (этап 2) будет опираться на тот же ключ.

**D-023 · 2026-10-04 · Состав фида проверяется при каждой отдаче.** Видимость списков для владельца роутера считается в момент запроса, а не только при сохранении, — отзыв доступа сразу убирает список из фида. Вложенные списки наследуют доступ от родителя.

**D-024 · 2026-10-04 · Токен фида — 43 символа base62.** ~256 бит, только буквы и цифры: не ломается ни в одном поле URL. Валидатор forkop для `domain_ip_lists` принимает любой `http(s)://` (проверено в `config/validator.uc`).

**D-025 · 2026-10-04 · Образ собирается в GitHub Actions, не на сервере.** GHCR `:latest` + `:sha-<7>`, сборка только после зелёных тестов. На домашний сервер нет Go и исходников, откат — сменой тега. Порт `172.17.0.1:8097` (8096 занят Jellyfin), `network_mode: bridge` из-за исчерпанного пула сетей Docker.

**D-026 · 2026-10-04 · Суффиксы — только ICANN-часть PSL (уточняет D-009).** Сначала отклонялись и сокращались домены по всему Public Suffix List, и `githubusercontent.com`, `notion.site`, `akamaized.net` нельзя было добавить («публичный суффикс»), а `raw.githubusercontent.com` не сокращался. Частная часть PSL — про изоляцию cookie, а для маршрутизации это обычные домены, которые и нужно пускать в туннель целиком. Теперь отклоняется только ICANN-суффикс целиком (`com`, `co.uk`), сокращение — до метки перед ICANN-суффиксом. Узкий хост по-прежнему можно добавить флажком «только этот хост».

**D-027 · 2026-10-04 · Удаление списка — физическое, очистка — версией.**
- **Очистка** удаляет все записи одной версией через `store.Mutate`: это обычная правка, её видно в истории и можно откатить. Право то же, что на удаление записей (owner/editor/admin): editor и так мог удалить всё по одной.
- **Удаление** — `DELETE FROM lists`, записи, история, права, вложения и место в фидах уходят каскадом. Архив (`archived_at`) не используется: без экрана восстановления он копит мёртвые данные и держит занятым адрес (`slug`), а пользователь, удаляя список, ждёт, что тот исчезнет. Страховка — подтверждение с числом фидов, запись `list.delete` в `audit_log` (slug, название, число записей и фидов) и ежедневный бэкап. Право — только owner/admin, не editor.
- **Переиспользование id.** SQLite отдаёт новой строке `max(id)+1`, поэтому после удаления последнего списка следующий получает тот же id. Отсюда две обязанности удаления: убрать список из индекса покрытия (`Index.RemoveList`), иначе записи нового списка будут «уже покрыты в этом списке», и сбросить кеш фидов (`feed.Builder.Forget`), иначе ключ «id:версия» (D-022) совпадёт со старым и роутер получит содержимое удалённого списка. Оба случая воспроизведены тестами.

**D-028 · 2026-10-04 · Адрес сервера в сети роутера — через `curl --resolve`.** Домашний роутер, обращаясь к домену listok, получает собственный внешний IP и попадает в свой LuCI (проверено). Варианты: ходить через служебный прокси forkop (зависит от VPN и гоняет трафик за границу и обратно), локальный DNS-оверрайд (меняет роутер шире, чем нужно), `--resolve` на LAN-IP сервера с тем же доменом и сертификатом NPM. Выбран последний: имя и TLS-проверка остаются, сеть не меняется. IP задаётся при выдаче ссылки установки (`?ip=` в ссылке, `server_ip` в `/etc/config/listok`); для роутеров в других сетях не нужен. `option proxy` оставлен на крайний случай.

**D-029 · 2026-10-04 · Успех применения — пересборка rule-set, а не код выхода.** `forkop list_update` выходит с 0, если пропустил запуск из-за чужого обновления, и с 1, если не скачался посторонний внешний список. Агент ждёт освобождения pid-lock forkop, вызывает обновление и считает его успешным, если `/tmp/sing-box/rulesets/<section>-lists-ruleset.json` пересобран после вызова и содержит сторожевую запись. Своя пересборка через внутренние функции forkop быстрее (без проверки GitHub и перекачки чужих списков), но forkop обновляется сам и внутренний API может поменяться — публичная команда надёжнее.

**D-030 · 2026-10-04 · Ссылка установки тратится только запросом curl или wget.** Ссылка одноразовая, а мессенджеры и браузеры открывают ссылки для предпросмотра — первый же такой запрос сжёг бы её. По User-Agent отличаем curl и wget (их и выполняют на роутере) от остальных; остальным — страница с командой и пояснением. Подделка User-Agent ничего не даёт: токен и так нужно знать.

**D-031 · 2026-10-04 · Long-poll: одно событие на всех.** `Notifier` будит все ожидающие запросы при любом изменении, каждый сам пересобирает свой фид из кеша и сравнивает ETag. Карта «список → фиды» не нужна, а цена ложного пробуждения — чтение ключа кеша из БД. При десятках роутеров это ничтожно; если станет заметно — сузить по `feed_lists`.

**D-032 · 2026-10-04 · Один long-poll на роутер и один `forkop list_update` на все секции (уточняет D-004).** В первой версии агента было по процессу procd и по curl на каждую секцию: на двух секциях ~10 МБ памяти и ~1,4 % ядра NanoPi R3S в покое — почти всё уходит на TLS-рукопожатие curl раз в минуту на секцию. `POST /agent/v1/wait` принимает версии всех секций и отвечает списком изменившихся: один процесс и один curl на роутер. forkop всё равно обновляет все секции разом, поэтому изменения нескольких секций применяются одним вызовом. `/f/…?wait=` остаётся для роутеров без агента и совместимости.

**D-033 · 2026-10-04 · Режим `poll` для слабых роутеров.** Тот же `/agent/v1/wait` с `wait: 0` раз в `interval` (минимум минута): между проверками у агента нет дочерних процессов, но изменение доходит с задержкой до интервала. Выбирается при выдаче ссылки установки, меняется в `/etc/config/listok`. По умолчанию `wait`: на большинстве современных роутеров его нагрузка незаметна.

**D-034 · 2026-10-04 · curl получает один корень, а не всё хранилище.** Замер на NanoPi R3S: запрос curl по HTTPS с хранилищем OpenWrt (~150 корней, 224 КБ) — ~30 тиков процессора, с одним нужным корнем — ~7,5; `--capath` не помогает, общий файл всё равно грузится. Агент при старте находит корень цепочки сервера через `openssl s_client` и `-issuer_hash`, проверяет запросом и передаёт `--cacert`. Проверка сертификата не ослабляется: с чужим корнем запрос падает с ошибкой 60. Корень не задаётся заранее, потому что зависит от выпуска сертификата (у Let's Encrypt — X1 или X2) и может смениться при продлении — тогда агент ищет его заново.

**D-035 · 2026-10-31 · Обмен списками — текстовым файлом, только включённые записи.** Чтобы делиться списком с другим экземпляром listok, нужен файл, который откроется где угодно. Выбран текст «запись на строку, комментарий после ` # `», а не JSON: его можно прочитать в мессенджере, поправить руками и собрать из чужого `.lst` — импорт принимает и файлы без комментариев. Выключенные записи не выгружаются: делятся рабочим списком, а полная копия со всем состоянием — это бэкап. Импорт разбирает голые домены с «только этот хост», иначе поддомены из выгрузки сократились бы до родителя; это же значит, что `www.example.com` из чужого файла останется как есть. Ссылки в выгрузке не встречаются, поэтому сокращаются как обычно. Импорт — одна версия `source=import` (значение было в схеме с 0001), откат через историю. Предел 4 МБ и 50 000 записей: проверка покрытия подсетей перебирает индекс, и огромный файл занял бы сервер надолго.

**D-036 · 2026-10-31 · forkop 2: список — локальный rule set ядра, применение — запись файла (уточняет D-004, D-029).** В forkop 2.0 убраны `domain_ip_lists` и `forkop list_update`, секции из LuCI стали анонимными с `option label`, а ядро `sing-box-forkop` само следит за локальным rule set и перечитывает его, подсети в nft переносит служба forkop по событию ядра (`forkop-integration.md`, «forkop 2.0»). Поэтому агент для 2.x только атомарно пишет `/etc/listok/<секция>.lst`, подключённый через `rule_set_with_subnets` (так же миграция forkop переносит `domain_ip_lists`), а успех проверяет сменой `revision` rule set в clash API — без пересборки всего forkop и без 20 с на проверку GitHub. Тег rule set берётся из сгенерированного конфига sing-box по пути файла, а не вычисляется своей копией `hash12`: формула тега — внутренняя деталь forkop. Ветка выбирается по `settings.config_version`, поддержка 1.x остаётся: роутеры обновляются не одновременно. Работу с конфигом forkop (поиск секции, подключение файла) установщик отдал агенту (`check`, `attach`): на ucode это одна реализация для установщика, агента и `uninstall`, а не разбор `uci show` в sh. Сторожевая запись в 2.x не нужна для регистрации rule set, но остаётся: файл без записей ядро не принимает.

**D-037 · 2026-10-31 · Адрес списка делается из названия.** Поле «Адрес» в форме нового списка пользователю ничего не давало: адрес нужен только для ссылок интерфейса, а фиды роутеров ссылаются на список по id. Теперь его делает сервис — транслитом названия (`Общий список` → `obshchii-spisok`), занятый получает `-2`, `-3`… Явный `slug` по-прежнему принимается сервисом (тесты, будущий API) и проверяется как раньше. Менять адрес после создания нельзя: старые ссылки на страницу списка сломались бы.

**D-038 · 2026-10-31 · Секции forkop вместо фидов в интерфейсе; агент подключает и отключает секции сам (уточняет D-036).** Пользователь, получивший listok, не понимал, что такое «фид» и почему его надо называть именем секции: в forkop есть только секции. Теперь агент присылает в `hello` секции forkop (название из LuCI, UCI-имя, тип), страница роутера показывает по карточке на секцию, и у подключённой списки отмечаются переключателями, которые сохраняются и применяются сразу. Фид остался внутренней сущностью сервиса (файл секции и ссылка на него).
- **Подключение секции — второй, кроме установки агента, случай перезапуска forkop.** Без него ядро не увидит новый файл. Поэтому перезапуск только по явной кнопке «Подключить секцию» с предупреждением в подтверждении; агент узнаёт о ней из `wait` (`added`) и делает это сам, переустановка не нужна. Правило в AGENTS.md уточнено.
- **Отключение — без перезапуска**: в файле секции остаётся только сторожевая запись, путь в forkop не трогается. Раньше на выключенный фид агент оставлял на роутере последний файл, и записи продолжали действовать.
- **Агент ставится без секций** (раньше установка требовала хотя бы один фид, 409): так естественнее — сначала агент, потом секции, которые он сам нашёл.
- **`added` только по запросу агента** (`added: true`): агент 0.3.x поля не знает и при новой секции на сервере вместо ожидания получал бы немедленный ответ раз за разом.
- **Секция по UCI-имени — та же секция.** Миграция forkop 2.0 сохранила имя `geo` у секции с названием `geoblock`; агент присылает оба, и сервер сопоставляет фид с секцией по любому, иначе одна секция показывалась бы двумя карточками.

**D-039 · 2026-11-01 · Ссылка установки агента хранится открыто и видна всегда (уточняет D-006).** Раньше команду показывали один раз после нажатия «Выдать ссылку», потому что в БД был только хеш токена; пользователю это казалось лишним шагом и шумом. Теперь токен ссылки хранится и открыто (`routers.install_token`), страница роутера показывает готовую команду сразу и сама выдаёт новую ссылку, если прежнюю использовали или ей осталось жить меньше часа. Режим и IP — параметры ссылки, а не часть токена, поэтому `app.js` подставляет их в команду на лету без запроса к серверу. Риск — тот же класс, что у ссылок секций: кто прочитал БД, может за оставшиеся до 24 ч поставить «агент» и получить токены секций, которые и так лежат в БД открыто. Ссылка одноразовая, после установки её токен стирается.

**D-040 · 2026-11-02 · Токены API и `/api/v1` с открытым CORS.** Расширению и команде на iPad нужен доступ без сессии. Токен отдельный на устройство, отзывается по одному, в БД только хеш (D-006), поэтому показывается один раз, в отличие от одноразовой ссылки установки (D-039): этот токен живёт долго и может менять списки. Чтобы не заполнять адрес и токен отдельно, страница выдаёт строку `адрес#токен`. `/api/v1` смотрит только заголовок и игнорирует cookie, поэтому CSRF здесь невозможен: маршруты выведены из `CrossOriginProtection`, иначе запрос из расширения получал бы 403, а CORS открыт для любого origin. API лежит в пакете `web`, а не в отдельном `api`: три обработчика поверх тех же сервисов.

**D-041 · 2026-11-02 · Расширение только для Chrome, на iPad команда вместо расширения.** Расширение Safari живёт внутри приложения. Apple требует платный Developer Program для запуска на устройстве, а сборки с бесплатного аккаунта живут 7 дней: поставить один раз и забыть нельзя. Web Share Target в Safari на iOS нет. Команда в меню «Поделиться» не требует ни аккаунта, ни Xcode и не истекает, хотя и нажатий чуть больше. Safari на Mac по той же причине не поддерживаем: без подписи разрешение сбрасывается при каждом запуске. Chrome на Mac — настоящий Chromium, расширение то же. Раздача — архивом с самого сервиса и «Загрузить распакованное»: репозиторий и магазин не нужны, ценой ручного обновления. Разрешения минимальные (`activeTab`, `storage`, адрес сервиса по запросу). Два адреса — по просьбе пользователя, хотя подмена домена в DNS роутера обычно проще (`extension.md`).

**D-042 · 2026-11-03 · Расширение видит запросы страницы и показывает незагруженные домены (уточняет D-041).** Домен из адресной строки часто ничего не даёт: ломается CDN или API на другом домене. Поэтому расширение наблюдает запросы вкладки через `webRequest`, и нужен доступ ко всем сайтам вместо минимальных разрешений. Сделано обязательным, без отдельного включения: важнее скорость, а ставят расширение осознанно и вручную. Домены остаются локально и уходят только на свой сервис. Критерий строже, чем у SwitchyOmega: она считает проблемой 5 с без заголовков и показывает то, что потом загрузилось. Здесь только сетевые ошибки и 15 с без заголовков, блокировщик и отмены страницей не считаются. Замедление так не поймать, поэтому есть свёрнутый блок «Остальные домены страницы» без галочек. Подсчёт и свод к доменам делает сервис (`/api/v1/check`), чтобы правило было одно: в расширении нет своей Public Suffix List.

**D-043 · 2026-11-03 · Команда для iPad раздаётся готовым файлом.** Собирать её руками в «Командах» сложно, а iOS импортирует только подписанные файлы, и подпись есть только на Mac. Поэтому файл генерируется из `shortcut/shortcut.go`, подписывается один раз на Mac, коммитится и встраивается в бинарник. Адреса и токена в нём нет, он безопасен для публичного репозитория и подходит всем: строку подключения спрашивает при добавлении. Списки берутся при запуске из `menu`, поэтому меняются без правки команды.
