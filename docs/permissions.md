# Права и предложения

## Роли на списке

| Роль | Где хранится | Может |
|---|---|---|
| owner | `lists.owner_id` | всё: записи, права, вложения, удаление списка, решения по предложениям |
| editor | `list_members` | добавлять, менять и удалять записи, очищать список целиком; решать предложения по строкам |
| viewer | `list_members` | видеть, подключать к своим фидам, **предлагать** |
| — | — | список не виден |

Админ (`users.is_admin`) видит и может всё. Пользователей создаёт только админ, саморегистрации нет.

Одна функция проверки: `auth.Can(user, list, action)`, где action ∈ `view, edit, propose, manage, decide`.

## Предложения

Создаются, если у пользователя есть `view`, но нет `edit`. Также их можно создать явно, кнопкой «Предложить» в своём списке.

**Тип `entries`**: набор строк `add`/`remove` с комментарием.
- Источник: строки из своего списка (галочками) или новые, введённые вручную. Нормализация та же, что при обычном добавлении.
- Решение: «принять всё», «отклонить всё» или по строкам → статус `accepted` / `partial` / `rejected`. Принятые строки применяются одной версией списка с `source='proposal'` и `proposal_id`.
- Автор может отозвать предложение (`withdrawn`), пока оно `open`.

**Тип `include`**: «подключить мой список X внутрь общего Y».
- После принятия в `list_includes` появляется `(Y, X)`. Дальше изменения в X сразу попадают во все фиды, где есть Y. Поэтому перед принятием показывается предупреждение и текущее содержимое X.
- Отключить вложение может владелец Y в любой момент.

Уведомления: SSE-счётчик в шапке. По желанию сообщение в Telegram владельцу целевого списка (`users.tg_chat_id`, бот только отправляет).

Перед принятием каждая строка проверяется на покрытие (`normalization.md`): если строка уже покрыта, она помечается и по умолчанию не применяется.
