# Интерфейс

htmx + Alpine.js, серверные шаблоны. Тёмная и светлая темы по `prefers-color-scheme`. Вёрстка рассчитана на телефон: основной сценарий «добавить с телефона».

## Главная `/`

- **Поле быстрого добавления** на всю ширину, в фокусе. Пока печатаешь (htmx `hx-trigger="input changed delay:300ms"`), под полем видно, что получится: `www.youtube.com/watch?v=… → youtube.com (домен)`, предупреждения о покрытии, выбор списка (по умолчанию последний), флажок «только этот хост», срок («навсегда / 1 ч / 24 ч / 7 дн»). Enter добавляет запись.
- **Роутеры**: карточки с зелёным, жёлтым или красным статусом. Зелёный: последний ETag актуален и агент выходил на связь меньше 2 мин назад. Жёлтый: отстаёт. Красный: молчит больше 10 мин. Обновляются по SSE.
- **Входящие предложения**: счётчик и последние 3.
- **Подсказки**: «12 новых хостов мимо туннеля» → `/suggestions`.
- **Последние изменения** по всем видимым спискам.

## Список `/lists/{slug}`

Таблица: значение, тип, комментарий, кто и когда добавил, срок, переключатель. Поиск по мере ввода и фильтр по типу. Массовая вставка в модальном окне: превью разбора по строкам до применения. Вкладки «История» и «Права». Для remote-списка: URL, время последнего обновления, ошибка, кнопка «обновить сейчас». Редактирование выключено.

## История

Лента версий: кто, когда, источник, `+N −M`. Клик по версии раскрывает diff (зелёные и красные строки). У каждой версии кнопка «откатить к этой».

## Предложения

Входящие и исходящие. Внутри предложения: diff с галочками по строкам, пометки «уже покрыто», кнопки «принять выбранное» и «отклонить». Поле для комментария к решению.

## Роутеры

Карточка роутера: версии агента, forkop и sing-box; фиды по секциям (ссылка с кнопкой копирования, состав списков галочками, перевыпуск); журнал опросов; кнопка «ссылка для установки» (команда с кнопкой копирования, живёт 24 ч).

## Подсказки

Группы по eTLD+1: `googlevideo.com (3 хоста, 120 МБ, дом)`. Действия: «добавить в список», «скрыть», «игнорировать всегда». Фильтр по роутеру.

## PWA

`manifest.webmanifest` с `share_target` → `/share`. На Android в меню «Поделиться» появляется listok и открывается быстрое добавление с подставленной ссылкой. Service worker минимальный: только чтобы приложение устанавливалось, офлайн не нужен.

## Как устроен фронт (для правок)

- Шаблоны: `internal/web/templates/layout.html`, `pages/*.html` (страница = layout + все partials + страница), `partials/*.html` (фрагменты для htmx). Ответы htmx рендерятся `renderFragments`: основной фрагмент + out-of-band (`hx-swap-oob`).
- Статика подключается через `{{static "файл"}}` → `/static/файл?v=<хеш всей статики>`, кеш на год. Новый файл в `static/` подхватывается сам.
- **CSP без `unsafe-eval` и inline-скриптов** (`middleware.go`), поэтому в htmx `allowEval:false`:
  - нельзя `hx-on:*`, фильтры триггеров `[...]`, `hx-vals='js:...'`;
  - вся логика на клиенте — только в `static/app.js`.
- **Таблицы и OOB**: `<tbody>`/`<tr>` для out-of-band оборачиваются в `<template>`, иначе HTML-парсер их выкидывает (см. `rows` в `partials/rows.html`). Если `<tr>` — основной ответ, обёртка не нужна.
- Коды ответа: 422 вставляется (ошибка валидации внутри фрагмента), остальные 4xx/5xx не вставляются, их показывает всплывашка `#toast`. Настройка — `meta[name=htmx-config]` в layout.
- Быстрое добавление и форма на странице списка: внешний `div` с `hx-post="/preview"` ловит всплывающие `input`/`change` из полей формы (живой предпросмотр), сама форма шлёт `submit` на добавление.
