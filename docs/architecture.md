# Архитектура

## Компоненты

```
 браузер/телефон (htmx)               роутер N (OpenWrt + forkop)
        │  сессия                            │  listok-agent (ucode, procd)
        ▼                                    │   ├─ POST /agent/v1/wait (long-poll по всем секциям)
 ┌───────────────────────────┐               │   ├─ GET /f/<token>.lst (ETag)
 │ listok (Go, один бинарник)│◄──────────────┘   └─ пишет /etc/listok/<section>.lst
 │  web (htmx)  │ /agent/v1  │                      (sing-box без перезапуска)
 │  feed        │ jobs       │
 │  SQLite (WAL) /data       │
 └───────────────────────────┘
        ▲ NPM (listok.<домен>), домашний сервер
```

## Поток данных

1. Пользователь добавляет запись. Ввод нормализуется (`normalization.md`), у списка поднимается `version`, в `list_versions`/`entry_changes` пишется история.
2. `feed.Notifier` будит все ожидающие long-poll запросы (одно событие на всех, D-031). Каждый сам сравнивает ETag своих фидов с учётом вложенных списков.
3. Агент получает от `/agent/v1/wait` изменившиеся секции, скачивает их `.lst` и атомарно записывает в `/etc/listok/`. Применение зависит от версии forkop (D-036): в 2.x ядро само перечитывает файл, а служба forkop переносит подсети в nft; в 1.x агент вызывает `forkop list_update`.
4. Агент докладывает итог в `/agent/v1/applied`, статус виден на странице роутера.
5. В `hello` агент присылает секции forkop. Секции из интерфейса подключаются и отключаются через ответ `/agent/v1/wait` (D-038, `router-agent.md`).
6. Этап 4, ещё не сделано: раз в N минут агент шлёт на сервер выжимку из clash API — хосты, которые ушли мимо туннеля. Из них получаются подсказки в интерфейсе.

## Фоновые задачи (внутри процесса)

Сейчас (`internal/jobs`, раз в час): чистка просроченных сессий и журнала опросов `feed_fetches`, ежедневный бэкап `VACUUM INTO /data/backups/...`.

Ещё не сделано:
- `remote-fetcher` (этап 3): обновляет списки типа `remote` (внешние `.lst`, например itdoginfo) по своему интервалу.
- `expirer` (этап 5): выключает временные записи (`entries.expires_at`).
- чистка старых наблюдений (этап 4).

## Свойства, на которые опирается дизайн

- Если сервис лежит, роутеры живут с последним файлом в `/etc`. Сервис не точка отказа для трафика.
- Входящих соединений к роутерам нет: роутеры только тянут данные сами. Работает за CGNAT.
- Один процесс, одна SQLite. Конкурентная запись почти отсутствует, WAL этого хватает.
