# Интеграция с forkop

Справка: что известно про forkop из чтения его кода на роутере пользователя (`/usr/lib/forkop`, forkop 1.0.x, sing-box 1.14.0-extended-2.7.1). Код прочитан 2026-09-27, проверки на живом роутере сделаны 2026-10-03. Если версия forkop изменилась, перепроверь пункты ниже.

Про forkop 2.x — отдельный раздел [ниже](#forkop-20): там почти всё устроено иначе, и агент поддерживает обе ветки (D-036).

## Факты из кода

- **«Domain and IP lists»** (`domain_ip_lists`) принимает URL и локальные пути к `.lst`. Строки делятся на домены (→ `domain_suffix`) и подсети (→ `ip_cidr`). Из них собирается local rule-set `/tmp/sing-box/rulesets/<section>-lists-ruleset.json`. Подсети дополнительно попадают в nft-сеты forkop, иначе трафик не дойдёт до sing-box.
- **`forkop list_update` не перезапускает sing-box.** Он пересобирает rule-set и добавляет подсети в nft (`nft add`). Перезапуск вызывает изменение UCI-конфига (LuCI), обновление компонентов forkop и смена DNS failover (последняя делает SIGHUP-перезагрузку sing-box).
- **Генератор регистрирует rule-set по факту на момент генерации** (`add_domain_ip_list_ruleset` в `singbox/generator.uc`):
  - rule-set попадает в route-правила, только если в файле уже есть хоть одно правило (`has_rules`);
  - rule-set попадает в **DNS-правила** (то есть домены получают FakeIP), только если в нём уже есть доменные матчеры (`has_domain_matchers`).
  Если на момент генерации список пуст или в нём только IP, домены, добавленные позже, **не заработают до рестарта**. Отсюда правило «сторожевой записи» в `feeds.md`.
- **URL или локальный путь.** Для URL файл в `/tmp` появляется только после фоновой загрузки, уже после генерации конфига. Получается гонка. Локальные пути импортируются синхронно при генерации, гонки нет. **Поэтому listok всегда подключается через локальный путь** `/etc/listok/<section>.lst`.
- Парсер `.lst` (`split_domain_subnet_file` в `nft/apply.uc`) вырезает комментарии `#` и `//` до конца строки и пропускает пустые строки. **Но** при генерации локальный файл читается другой функцией (`import_plain_list` в `routing/rulesets.uc`) без вырезания комментариев. Строка с комментарием там считается невалидной и пропускается. Вывод: в фиде **никаких комментариев**.
- «Rule sets» (`rule_set`) → remote rule-set sing-box с `update_interval` = `settings.update_interval` (1d). Подсети из него в nft не попадают без `rule_set_with_subnets`. Для listok не используется.
- Cron forkop: `forkop list_update_if_due` в полночь. Строки cron forkop помечены `# forkop-*`.
- **`forkop list_update` (forkop 1.0.5, `components/updates.uc`)** — проверено 2026-10-04:
  - pid-lock `/var/run/forkop_list_update.pid`. Если обновление уже идёт, пишет «Another lists update is already running, skipping» и выходит с **кодом 0**, как при успехе;
  - обновляет все секции целиком: DNS-проверка (без прокси), проверка доступа к GitHub (до 10 попыток), перекачка всех списков по ссылкам. Один вызов — около 20 с;
  - код **1**, если не скачался любой внешний список, даже когда локальные файлы применились.

  Отсюда D-029: агент судит об успехе по пересборке rule-set секции, а не по коду выхода.
- `download_lists_via_proxy=1` → списки по ссылкам качаются через служебный mixed-прокси forkop (`127.0.0.1:4534`), то есть через VPN-выход.
- **Роутер не достаёт до собственного внешнего IP.** Домен listok указывает на белый IP дома, а это адрес самого роутера: запрос с роутера попадает в его uhttpd/LuCI (самоподписанный сертификат OpenWrt), а не в проброс на сервер. Через прокси forkop — работает. Поэтому для роутера в одной сети с сервером агент использует `server_ip` (D-028).
- LuCI: поле «Domain and IP lists» — DynamicList (после вставки нажать «+»). «Save & Apply» с проверкой может **откатить** изменение, если перезапуск forkop оборвал связь браузера с роутером; черновик остаётся в сессии (`/var/run/rpcd/uci-*/forkop`), и форма показывает значение, которого нет в `/etc/config/forkop`. Лечится «Apply unchecked».
- forkop сам обновляет свои компоненты (`component_update_check_enabled=1`) и после этого перезапускается. 2026-10-03 в 20:25 это и вызвало гонку: rule-set discord.lst в живом конфиге отсутствовал.

## forkop 2.0

Прочитан исходный код релиза 2.0.0 (`github.com/ushan0v/forkop`, 2026-10-27) и его ядра `sing-box-forkop`, 2026-10-31. На живом роутере ещё не проверялось.

- **Секции.** Колонка «Name» в LuCI — это `option label`. Секции, созданные в интерфейсе, **анонимные** (`cfg…`), поэтому `uci get forkop.main` их не находит (так и упал установщик агента 0.2.x). Секции, перенесённые миграцией из 1.0.5, сохраняют имя и получают `label`. Метки уникальны. Агент ищет секцию сначала по `label`, потом по имени.
- **Версия** — `forkop.settings.config_version` (`2.0.0`); в 1.x этой опции нет.
- **`domain_ip_lists` больше нет.** Миграция 1.0.5 → 2.0.0 переносит его в `rule_set_with_subnets` («Наборы правил» с флажком «Учитывать IP-адреса и подсети»), у DNS-секций — в `rule_set` (там подсети запрещены валидатором). Локальный файл без единой записи миграция выбрасывает: ядро с таким не стартует.
- **Свой список — локальный rule set ядра**: путь `/…` превращается в `route.rule_set` `{type: "local", format: "auto", path}` с тегом `inline-custom-<hash12(путь)>-ruleset`. Формат `auto` понимает текстовый список: по записи на строку, `example.com` — домен с поддоменами, подсети IPv4/IPv6, комментарии `#` и `//`. Непонятная строка — ошибка ядра. Rule set регистрируется в маршрутах и DNS **всегда**, независимо от содержимого (проверки `has_rules`/`has_domain_matchers` из 1.x нет).
- **Горячая перезагрузка встроена в ядро.** `LocalRuleSet` следит за файлом через `fswatch` (наблюдает каталог, ловит `Create`/`Write` по имени файла, то есть и атомарный `mv`), перечитывает его и увеличивает `revision`. Ошибка разбора только пишется в журнал sing-box, ревизия не растёт.
- **Подсети в nft переносит служба forkop** `forkop-ruleset-sync`: ждёт `GET /providers/rules/events` в clash API и при изменении заливает подсети rule set в nft-сеты секции одной транзакцией с `flush` — удалённые подсети теперь тоже уходят (в 1.x сеты только пополнялись, П-2).
- **`forkop list_update` больше нет**, как и `/tmp/sing-box/rulesets/`. Обновление наборов по ссылкам — внутри ядра (`update_interval`).
- **clash API**: адрес и секрет — в сгенерированном конфиге sing-box (`forkop.settings.config_path`, по умолчанию `/etc/sing-box/config.json`), `experimental.clash_api.external_controller` и `secret`; `0.0.0.0`/`::` означают локальный адрес, порт по умолчанию 9090. `GET /providers/rules/<tag>` → `{name, format, updatedAt, revision, ip_cidr}`.
- `/etc/init.d/forkop reload` есть, как и раньше.

Отсюда схема агента для 2.x: путь `/etc/listok/<секция>.lst` в `rule_set_with_subnets` секции, применение — только атомарная запись файла, успех — сменившаяся `revision` rule set в clash API (`router-agent.md`).

## Результаты проверок (2026-10-03, домашний роутер)

- **П-1. Горячая перезагрузка — подтверждено.** Тест на отдельном временном sing-box 1.14 (DNS на 127.0.0.77, local rule-set, fakeip-сервер). Новые домены начинали получать FakeIP через ≤3 с без перезапуска процесса при трёх способах записи файла: перезапись на месте, удаление и создание заново (так делает forkop), атомарный `mv`. Удалённые домены переставали матчиться.
- **П-2. nft-сеты только пополняются — подтверждено по коду.** В `list_update` нет `flush` и `delete element`, удалённая подсеть остаётся в сете до рестарта forkop. Последствие безвредное: такой трафик заворачивается в sing-box, не матчится ни одним правилом и уходит в `final` (direct).
- **П-3. Комментарии** — см. выше: в фиде их не будет.
- **П-4. DNS-кеш клиента — теория, не измерено.** На роутере dnsmasq с `cachesize=0`, кеширует только сам клиент. Если устройство уже получило настоящий IP домена, оно ходит мимо туннеля до истечения TTL (обычно от минуты до нескольких минут). В интерфейсе после добавления показывать подсказку «если не заработало — обнови страницу через минуту / сбрось DNS».
- **П-5. Трафик самого роутера — в порядке.** Роутер резолвит через dnsmasq → sing-box (`/etc/resolv.conf` = 127.0.0.1). Его исходящий трафик проходит через цепочку `mangle_output` forkop. Домены не из списков идут напрямую (проверено `curl` с роутера → 200). Агент будет ходить до сервера listok так же.
- **П-6. Пустой список опасен.** Если после импорта rule-set пуст, `cleanup_empty_ruleset` удаляет файл. Если пусто на момент генерации, rule-set не регистрируется (см. выше). Защита: агент никогда не пишет пустой фид, а сервер всегда добавляет сторожевую запись (`feeds.md`).
