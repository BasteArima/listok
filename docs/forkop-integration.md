# Интеграция с forkop

Справка: что известно про forkop из чтения его кода на роутере пользователя (`/usr/lib/forkop`, forkop 1.0.x, sing-box 1.14.0-extended-2.7.1). Код прочитан 2026-09-27, проверки на живом роутере сделаны 2026-10-03. Если версия forkop изменилась, перепроверь пункты ниже.

## Факты из кода

- **«Domain and IP lists»** (`domain_ip_lists`) принимает URL и локальные пути к `.lst`. Строки делятся на домены (→ `domain_suffix`) и подсети (→ `ip_cidr`). Из них собирается local rule-set `/tmp/sing-box/rulesets/<section>-lists-ruleset.json`. Подсети дополнительно попадают в nft-сеты forkop, иначе трафик не дойдёт до sing-box.
- **`forkop list_update` не перезапускает sing-box.** Он пересобирает rule-set и добавляет подсети в nft (`nft add`). Перезапуск вызывает изменение UCI-конфига (LuCI), обновление компонентов forkop и смена DNS failover (последняя делает SIGHUP-перезагрузку sing-box).
- **Генератор регистрирует rule-set по факту на момент генерации** (`add_domain_ip_list_ruleset` в `singbox/generator.uc`):
  - rule-set попадает в route-правила, только если в файле уже есть хоть одно правило (`has_rules`);
  - rule-set попадает в **DNS-правила** (то есть домены получают FakeIP), только если в нём уже есть доменные матчеры (`has_domain_matchers`).
  Если на момент генерации список пуст или в нём только IP, домены, добавленные позже, **не заработают до рестарта**. Отсюда правило «сторожевой записи» в `feeds.md`.
- **URL или локальный путь.** Для URL файл в `/tmp` появляется только после фоновой загрузки, уже после генерации конфига. Получается гонка. Локальные пути импортируются синхронно при генерации, гонки нет. **Поэтому listok всегда подключается через локальный путь** `/etc/listok/<section>.lst`.
- Парсер `.lst` (`split_domain_subnet_file` в `nft/apply.uc`) вырезает комментарии `#` и `//` до конца строки и пропускает пустые строки. **Но** при генерации локальный файл читается другой функцией (`import_plain_list` в `routing/rulesets.uc`) без вырезания комментариев. Строка с комментарием там считается невалидной и пропускается. Вывод: в фиде **никаких комментариев**.
- «Rule sets» (`rule_set`) → remote rule-set sing-box с `update_interval` = `settings.update_interval` (1d). Подсети из него в nft не попадают без `rule_set_with_subnets`. Для listok не используется.
- Cron forkop: `forkop list_update_if_due` в полночь. Строки cron forkop помечены `# forkop-*`.
- forkop сам обновляет свои компоненты (`component_update_check_enabled=1`) и после этого перезапускается. 2026-10-03 в 20:25 это и вызвало гонку: rule-set discord.lst в живом конфиге отсутствовал.

## Результаты проверок (2026-10-03, rw-router)

- **П-1. Горячая перезагрузка — подтверждено.** Тест на отдельном временном sing-box 1.14 (DNS на 127.0.0.77, local rule-set, fakeip-сервер). Новые домены начинали получать FakeIP через ≤3 с без перезапуска процесса при трёх способах записи файла: перезапись на месте, удаление и создание заново (так делает forkop), атомарный `mv`. Удалённые домены переставали матчиться.
- **П-2. nft-сеты только пополняются — подтверждено по коду.** В `list_update` нет `flush` и `delete element`, удалённая подсеть остаётся в сете до рестарта forkop. Последствие безвредное: такой трафик заворачивается в sing-box, не матчится ни одним правилом и уходит в `final` (direct).
- **П-3. Комментарии** — см. выше: в фиде их не будет.
- **П-4. DNS-кеш клиента — теория, не измерено.** На роутере dnsmasq с `cachesize=0`, кеширует только сам клиент. Если устройство уже получило настоящий IP домена, оно ходит мимо туннеля до истечения TTL (обычно от минуты до нескольких минут). В интерфейсе после добавления показывать подсказку «если не заработало — обнови страницу через минуту / сбрось DNS».
- **П-5. Трафик самого роутера — в порядке.** Роутер резолвит через dnsmasq → sing-box (`/etc/resolv.conf` = 127.0.0.1). Его исходящий трафик проходит через цепочку `mangle_output` forkop. Домены не из списков (`baste.ru`) идут напрямую: `curl https://baste.ru` → 200. Агент будет ходить до `listok.baste.ru` так же.
- **П-6. Пустой список опасен.** Если после импорта rule-set пуст, `cleanup_empty_ruleset` удаляет файл. Если пусто на момент генерации, rule-set не регистрируется (см. выше). Защита: агент никогда не пишет пустой фид, а сервер всегда добавляет сторожевую запись (`feeds.md`).
