# HTTP-маршруты

Четыре группы маршрутов с разной аутентификацией. Снаружи доступны все: интерфейс открыт и защищён паролем (D-012). Что ещё не сделано, помечено этапом.

## 1. Публичные, по токену в пути (без сессии)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/f/{token}.lst` | Содержимое фида, `text/plain`. `ETag` + `If-None-Match` → 304. `?wait=N` — long-poll: при совпавшей версии ждёт изменения до N с (не больше `LISTOK_LONGPOLL_MAX`), потом 304. В журнал опросов пишется один итог запроса. |
| GET | `/install/{token}` | sh-установщик агента (`?ip=` — IP сервера в сети роутера, D-028; `?mode=poll&interval=<сек>` — режим опроса, 60…86400). Одноразовый, 24 ч; тратится только запросом curl или wget, остальным — страница-подсказка (D-030). 404 — ссылка недействительна. Секций у роутера может не быть: агент ставится без них, секции подключаются потом в интерфейсе (D-038). Ошибки — телом `echo …; exit 1`. |
| GET | `/agent/listok-agent.uc` | Текущая версия агента, для самообновления (этап 5, ещё не сделано). |

Неизвестный токен → `404` без подробностей. `/f/`, `/install/`, `/agent/v1` ограничены 120 запросами в минуту с IP (429 + `Retry-After`).

## 2. Агент: `/agent/v1`, заголовок `Authorization: Bearer <agent_token>`

| Метод | Путь | Тело / ответ |
|---|---|---|
| POST | `/agent/v1/hello` | `{agent_version, forkop_version, singbox_version, mode, interval_s, sections:[...], forkop_sections:[{name, uci, action}]}` → `{feeds:[{section, token, url}], agent_version, report_interval_s, report_enabled}`. Обновляет `last_seen_at`, `last_ip`, версии и режим роутера (пустые не затирают). `forkop_sections` (агент 0.4.0+) — секции forkop на роутере: название из LuCI, UCI-имя, тип; до 64, повторы и пустые отбрасываются; без поля (агент старше) прежний список не трогается. `token` — актуальный токен фида: агент подхватывает перевыпущенную ссылку. `agent_version` в ответе — актуальная на сервере |
| POST | `/agent/v1/wait` | `{feeds: {секция: etag}, wait, added}` → `{changed:[...], gone:[...], added:[...]}`. Long-poll по всем секциям роутера сразу (D-032): ответ, как только изменилась или пропала (отключена в интерфейсе или выключена) хоть одна, или пустой по истечении `wait` (не больше `LISTOK_LONGPOLL_MAX`). `added: true` (агент 0.4.0+) — сообщать и о секциях, которые подключили в интерфейсе, а у агента их нет; агенту без флага они не сообщаются, иначе он получал бы немедленный ответ раз за разом. `feeds` может быть пустым (агент без секций), до 64 секций; плохое имя секции → 400. `wait: 0` — проверить и ответить сразу (режим `poll`). Обновляет `last_seen_at` |
| POST | `/agent/v1/report` | `{observations:[{host, ip, network, port, rule, outbound, hits, bytes}]}` → 204 (этап 4, ещё не сделано) |
| POST | `/agent/v1/applied` | `{section, etag, ok, error?}`: результат применения в forkop (`router-agent.md`) → 204. Неизвестная секция → 400 |

Неверный или отозванный токен агента → 401. Тело JSON до 64 КБ. В БД хранится только sha256 токена агента.

## 3. JSON API: `/api/v1`, заголовок `Authorization: Bearer <api_token>`

Для расширения браузера, команд на iPad и скриптов (`extension.md`). Права те же, что у владельца токена. Сессия из cookie не действует. CORS открыт для любого origin, защита от CSRF на эти маршруты не распространяется: без токена в заголовке запрос не пройдёт (D-040). Те же 120 запросов в минуту с IP.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/lists` | `{user, lists:[{slug, title, entries, can_edit}]}`: видимые списки, `entries` — включённые записи |
| GET | `/api/v1/check?q=...&exact=1` | `{items:[...]}`: как разберётся ввод и где он уже покрыт. Ничего не меняет |
| POST | `/api/v1/lists/{slug}/entries` | `{input, comment?, exact_host?}`: сырой ввод, можно целую ссылку, сервер нормализует → `{message, items:[...]}`. Одна версия с `source=api`. `message` — итог фразой, для показа. Повтор безопасен. Без права на запись 403, невидимый список 404, пустой ввод или длинный комментарий 422 |

Элемент `items`: `{input, value, kind, status, error, warnings:[...], covered_by:[{list, slug, value}]}`. `status` только после добавления: `added`, `exists`, `covered`, `error`. Ошибка разбора записи — не ошибка запроса: ответ 200, `status=error`.

Ещё не сделано (этап 5): `GET /api/v1/lists/{slug}/entries`, `DELETE /api/v1/lists/{slug}/entries/{value}`, `POST /api/v1/quick` (добавить в список по умолчанию), `ttl` при добавлении. Без права на запись — создание предложения (этап 3).

Ошибки в формате `{"error": "code", "message": "по-русски"}`.

## 4. Веб-интерфейс (сессия, htmx)

Страницы отдают полный HTML. При заголовке `HX-Request` отдаётся только фрагмент (`partials/`). Все изменяющие запросы идут через POST/DELETE/PATCH и защищены `http.CrossOriginProtection`.

| Путь | Экран |
|---|---|
| `GET /setup`, `POST /setup` | Создание первого админа по setup-токену из лога. Доступно, только пока пользователей нет (`deploy.md`) |
| `GET /login`, `POST /login`, `POST /logout` | Вход. Ограничение частоты: 5 неудачных попыток за 15 мин на IP+логин, дальше пауза с ростом |
| `GET /` | Главная: быстрое добавление, списки, последние изменения |
| `GET /lists`, `POST /lists` | Списки. `POST`: `title`, `description`; `slug` необязателен — без него адрес делается из названия (D-037) |
| `POST /preview` | Живой разбор ввода (`input`, `list`, `exact`) → фрагмент `preview`. Ничего не пишет |
| `POST /quick` | Быстрое добавление с главной → итог + OOB: очистка поля, лента изменений. Запоминает список в cookie `listok_last_list` |
| `GET /lists/{slug}` | Записи, поиск, фильтры (`q`, `kind` = domain/cidr) |
| `GET /lists/{slug}/rows` | Только `<tbody id="rows">` для поиска |
| `POST /lists/{slug}/entries` | Добавить пачку → итог + OOB: таблица (в `<template>`), счётчики |
| `GET /lists/{slug}/export` | Файл списка `{slug}.txt` (`text/plain`, attachment): включённые записи с комментариями, формат — `normalization.md`, «Файл списка». Любая роль на списке |
| `POST /lists/{slug}/import` | `multipart/form-data`, поле `file` (до 4 МБ, до 50 000 записей, UTF-8): добавить записи из файла одной версией (`source=import`, `message` «импорт из файла <имя>»). Ответ: итог (только непринятые строки, до 200) + OOB: таблица, счётчики. Без файла, не UTF-8, слишком большой — 422 с сообщением. Нужна роль owner/editor/admin |
| `GET /lists/{slug}/entries/{id}/row`, `…/edit` | Строка таблицы в режиме просмотра / правки комментария |
| `PATCH /lists/{slug}/entries/{id}` | Комментарий, вкл/выкл |
| `DELETE /lists/{slug}/entries/{id}` | Удалить |
| `POST /lists/{slug}/entries/bulk` | Массовое действие над выбранными: `op` = delete / disable / enable, `id` повторяется. Одна версия на действие (`message` «удаление выбранных (N)» и т.п.). id чужого списка или уже удалённой записи пропускается, больше 5000 id или неизвестный `op` — 400. Ответ: `<tbody id="rows">` с текущим фильтром (`q`, `kind` из формы фильтров) + OOB счётчики. Нужна роль owner/editor/admin |
| `POST /lists/{slug}/clear` | Удалить все записи одной версией (`message` «очистка списка»), список остаётся. Откатывается через историю. htmx: 204 + `HX-Redirect` на список. Нужна роль owner/editor/admin |
| `POST /lists/{slug}/delete` | Удалить список насовсем вместе с историей (D-027), запись `list.delete` в `audit_log`. htmx: 204 + `HX-Redirect` на `/lists`. Только owner/admin |
| `GET /lists/{slug}/history` | Лента версий (по 50, дальше `…/history/more?before=N` по прокрутке) |
| `GET /lists/{slug}/history/{v}` | Фрагмент: изменения версии v |
| `POST /lists/{slug}/rollback/{v}` | Откат к состоянию после версии v (0 = пустой список). htmx: 204 + `HX-Redirect` на историю. Нужна роль owner/editor/admin |
| `GET /routers`, `POST /routers` | Роутеры пользователя (админ видит все), создание |
| `GET /routers/{id}`, `POST /routers/{id}`, `POST /routers/{id}/delete` | Страница роутера: секции forkop, агент, ссылки, журнал; правка; удаление |
| `POST /routers/{id}/feeds` | Подключить секцию: `section` (+ необязательно `list`, несколько). Кнопка «Подключить секцию» и форма «вручную» |
| `GET /routers/{id}/sections/{feed}` | Фрагмент: карточка подключённой секции (её переспрашивает сама карточка, пока изменение доходит до роутера) |
| `POST /feeds/{id}/lists` | Состав секции, `list` повторяется. htmx — ответ: карточка секции (переключатели шлют его при каждом щелчке); обычная форма — 303 |
| `POST /feeds/{id}/toggle` \| `regenerate` \| `delete` | Вкл/выкл, новая ссылка (старая сразу 404), отключение секции от listok |
| `POST /routers/{id}/install` | «Другая ссылка»: выдать новую ссылку установки агента (прежняя перестаёт работать). `mode` (`wait` или `poll`), `interval` (минут, 1…1440, для `poll`), `server_ip` (необязательно) проверяются и подставляются в команду. Ответ — страница роутера. Сама ссылка показывается на странице всегда: `GET /routers/{id}` выдаёт новую, если действующей нет или ей осталось меньше часа (D-039) |
| `POST /routers/{id}/agent/revoke` | Отвязать агент: забыть его токен. htmx: 204 + `HX-Redirect` |
| `GET /connections`, `POST /connections` | Токены API, расширение, команда для iPad. `POST`: `name`; ответ — та же страница с токеном и строкой подключения, показывается один раз |
| `POST /connections/{id}/revoke` | Отозвать токен. htmx: 204 + `HX-Redirect` |
| `GET /extension.zip` | Архив расширения для установки вручную |

Действия с подтверждением (`hx-confirm`) приходят от htmx и получают 204 + `HX-Redirect`, обычные формы — 303.
