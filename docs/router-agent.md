# Агент на роутере (`agent/`)

## Почему ucode

На роутере только busybox, без python и jq. ucode уже стоит: на нём написан forkop. В ucode есть JSON, `fs` и запуск процессов, поэтому разбор clash API и отчёты пишутся нормально, без sed по JSON. HTTP через `curl` (он есть на роутерах пользователя).

## Файлы на роутере

```
/usr/bin/listok-agent            # ucode-скрипт (agent/listok-agent.uc)
/etc/init.d/listok-agent         # procd: по экземпляру на каждую секцию (agent/listok-agent.init)
/etc/config/listok               # uci: server, необязательный server_ip, token агента, секции и токены фидов; права 600
/etc/listok/<section>.lst        # последний полученный фид (флеш: overlay, переживает ребут)
/etc/listok/<section>.etag
/tmp/listok/                     # временные файлы запросов
```

Команды: `listok-agent run <секция>` (цикл, его запускает procd), `sync <секция>` (одна загрузка без forkop, для установщика), `status`, `uninstall`, `version`.

## Как агент ходит к серверу

`curl` с `--connect-timeout 10`. Если в конфиге есть `server_ip`, добавляется `--resolve <хост>:<порт>:<server_ip>` (D-028): роутер в одной сети с сервером, обращаясь к домену listok, получает собственный внешний IP и попадает в свой LuCI (проверено на домашнем роутере: отвечает самоподписанный сертификат OpenWrt). Есть и `option proxy` (`curl -x`), например служебный прокси forkop `http://127.0.0.1:4534` — тогда запросы идут через VPN.

## Цикл синхронизации (по процессу procd на секцию)

1. `GET <server>/f/<token>.lst?wait=55` с `If-None-Match: <etag>`.
2. `304` → сразу следующий запрос (если 304 пришёл быстрее 5 с — сервер не держит long-poll, пауза 30 с).
3. `200` → проверка: первой строкой `listok-sentinel.invalid`, остальные строки — домен, IPv4- или IPv6-подсеть. Не прошло — в журнал, пауза с ростом. Прошло и отличается от файла — атомарно `mv` поверх `/etc/listok/<section>.lst`, сохранить etag. На флеш пишем только при реальном изменении.
4. Изменился файл → `forkop list_update` (D-029):
   - если идёт чужое обновление (`/var/run/forkop_list_update.pid` с живым процессом) — ждать до 5 мин;
   - **код выхода не используется**: при чужом обновлении forkop пишет «уже идёт» и выходит с 0, а при недоступном внешнем списке (тот же discord.lst) — с 1, хотя наш локальный файл применился;
   - успех — `/tmp/sing-box/rulesets/<section>-lists-ruleset.json` пересобран после вызова и содержит сторожевую запись. Иначе ещё две попытки через 10 с.

   Применение занимает около 20 с: forkop проверяет доступ к GitHub и перекачивает все списки по ссылкам.
5. `POST /agent/v1/applied` с результатом (и после `200` без изменений файла — тоже, с `ok: true`).
6. `404` (ссылку перевыпустили, фид удалён или выключен) → пауза 5 мин. Сеть или 5xx → пауза 5 с, удваивается до 5 мин. Файл не трогается.
7. `hello` при старте и раз в час: версии агента, forkop и sing-box (из `opkg list-installed`). Если на сервере есть фид секции, которой нет в локальном конфиге, — предупреждение в журнал: новые секции подхватываются переустановкой.

Журнал: `logread -e listok-agent`.

## Проверка без изменений на роутере

`LISTOK_UCI_DIR`, `LISTOK_STATE_DIR`, `LISTOK_TMP_DIR` переносят конфиг и файлы (например, в `/tmp/lt`), `LISTOK_DRY_RUN=1` не вызывает forkop, `LISTOK_DEBUG=1` дублирует журнал в stderr. Так агент проверялся на домашнем роутере 2026-10-04 против локального listok через `ssh -R`: изменение доходило меньше чем за секунду, перевыпуск ссылки давал 404 сразу, обрыв связи — паузы 5 → 10 → 20 с. Синтаксис без запуска: `ucode -c -o /tmp/x.ucb listok-agent.uc`.

## Отчёты из clash API (этап 4, ещё не сделано)

- Раз в 30 с: `GET http://127.0.0.1:9090/connections` (с `Authorization: Bearer <secret>`, если задан `yacd_secret_key`).
- Берутся соединения, у которых в `chains` есть `direct-out`, а `metadata.host` не пустой и не IP. Копятся в памяти: host → hits, bytes, пример IP/порта/сети, rule.
- Раз в `report_interval_s` (по умолчанию 300) уходит на `/agent/v1/report`, накопленное очищается.
- Локальный фильтр не отправляет домены LAN и `*.lan`/`*.local`, а также то, что уже есть в собственных фидах.
- Выключается через `report_enabled` (на сервере для роутера и в uci локально). Для роутеров других пользователей по умолчанию **выключено**.

На сервере отчёты попадают в `observations`. Они проходят через `suggestion_ignores` и проверку покрытия. В интерфейсе показываются хосты со статусом `new`, сгруппированные по eTLD+1: «добавить в список…», «скрыть», «игнорировать шаблон».

## Установка

Карточка роутера → «Агент на роутере» → «Выдать ссылку установки» (необязательно: IP сервера в сети роутера). Появляется команда, её выполняют на роутере под root:

```
curl -fsSL [--resolve listok.example.com:443:<IP>] 'https://listok.example.com/install/<token>[?ip=<IP>]' | sh
```

Ссылка одноразовая, живёт 24 ч, в БД хранится только её хеш. **Тратится только запросом от curl или wget** (D-030): браузер и предпросмотр ссылки в мессенджере получают страницу-подсказку. Без включённых фидов ссылка не тратится, установщик объясняет почему.

Установщик (`agent/install.sh.tmpl`, токены подставляет сервер):
1. Проверяет root, forkop, ucode, curl и что все секции фидов есть в forkop.
2. Бэкап `/etc/config/forkop.bak-listok-<дата>`.
3. Кладёт агент, init-скрипт и `/etc/config/listok` (с `umask 077`).
4. Первая загрузка каждого фида (`listok-agent sync`), чтобы `/etc/listok/*.lst` существовали.
5. В forkop: из `domain_ip_lists` секции убираются ссылки на фиды этого сервера (`<server>/f/…`, если их вставляли вручную), добавляется `/etc/listok/<section>.lst`. `uci commit forkop`, `/etc/init.d/forkop reload` — **единственный перезапуск forkop**.
6. `listok-agent` enable + restart.

Удаление: `listok-agent uninstall` убирает пути `/etc/listok/…` из forkop (forkop перезапустится), останавливает и выключает службу, удаляет файлы. На сервере «Отвязать агент» забывает токен агента (фиды продолжают отдаваться).

Самообновление (этап 5, ещё не сделано): `hello` уже возвращает актуальную версию, карточка роутера показывает «есть новая». Агент будет скачивать `/agent/listok-agent.uc`, проверять sha256 и перезапускаться.
